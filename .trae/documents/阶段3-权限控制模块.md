# 阶段3：权限控制模块实现方案

## Context

阶段2 已实现工具调用能力（list_files / read_file / grep_search 均为只读，自动放行）。本阶段对齐 BearCode 权限设计，新增**编辑类工具**（write_file、edit_file）并引入**权限确认机制**：只读工具自动放行，文件写入/修改类工具触发前端权限弹窗，用户同意才执行，拒绝则跳过该工具（AgentLoop 继续，结果回填 LLM）。权限状态单次有效、不缓存。

核心工程挑战是 AgentLoop 的 **Suspend/Resume**：执行到 Edit 工具时需挂起等待用户决策，通过独立 HTTP 端点回传决策后唤醒。

---

## 核心机制：PermissionGate（挂起/唤醒）

新建 `server/src/agent/permission/PermissionGate.ts`，用 Promise + resolver 协调挂起：
- `request(req, signal)`：返回 Promise 挂起调用方；注册 120s 超时自动拒绝；监听 abort signal 联动中断
- `resolve(permissionId, decision)`：唤醒（幂等，已决返回 false）
- `cancel(permissionId)` / `cancelAll(reason)`：主动拒绝并清理（连接断开/中断时）
- `permissionId` 复用 `toolCallId`（单次工具单次权限）
- 内部 `Map<permissionId, {resolve, timerId, signal}>`

关键风险防御（来自 Plan 验证）：
1. **SSE 断开清理**：chat.ts 新增 `res.on('close')` → `gate.cancelAll()` + `loop.abort()` + 清理两个 Map（幂等守卫）
2. **超时 timer 泄漏**：resolve/cancel 均 `clearTimeout`
3. **重复 resolve 幂等**：已决时返回 false，不抛错
4. **权限等待不计入 30s 执行超时**：permissionChecker 在 executor 构建 AbortController **之前**调用

## 端到端验证

1. **静态**：前端 `cd client && npm run build`（Vite strict 必过）；后端类型自查
2. **只读不弹窗**：发"列出目录"→ 无 permission_request，tool_result.ok=true
3. **write 同意**：发"创建 hello.txt 内容 Hi"→ 收 tool_call_start + permission_request → 弹窗显示路径 hello.txt → 点同意 → tool_result.ok=true → 验证文件真实创建
4. **write 拒绝**：弹窗点拒绝 → tool_result.ok=false content="用户拒绝授权" → 文件未创建 → LLM 回复"用户拒绝"
5. **超时**：弹窗不操作等 120s → 自动拒绝 → 前端倒计时归零弹窗关闭
6. **中断联动**：弹窗期点中断按钮 → gate.cancelAll → SSE error/done → 弹窗关闭
7. **断开清理**：弹窗期关浏览器标签 → `GET /api/health` 的 activeRequests 归零
8. **重复 resolve 幂等**：双击同意 → 第二次 POST 返回 success:false，工具只执行一次
9. **edit 唯一性**：oldString 出现 2 次 → 报错要求更长上下文 → LLM 自我修正后成功
10. **路径越界**：write 到 `../../etc/passwd` → 工具拒绝（即便同意也拦截，双重防御）
11. **PermissionMode 短路**：临时改回 BypassPermissions → write 直接执行不弹窗（向后兼容）
12. **并发 Edit 串行**：LLM 一次返回 2 个 write → 第一个弹窗→同意→执行→第二个弹窗（不同时弹两个）
